# TreatmentLane

TreatmentLane is a transparent U.S. directory for addiction treatment, recovery, and mental health resources. The production site uses Next.js, TypeScript, and Neon Postgres on Vercel.

## Local development

```bash
npm install
cp .env.example .env.local
npm run dev
```

The site works without a database connection, but the directory will be empty and submission forms will return a clear temporary-unavailable message.

## Production setup

1. Create or connect a Neon Postgres database and run `database/schema.sql` in its SQL editor.
2. Copy `.env.example` to `.env.local` for local work.
3. Add the variables from `.env.example` to the hosting environment.
4. Deploy to Vercel and verify the preview URL.
5. Add `treatmentlane.com` and `www.treatmentlane.com` to the Vercel project.
6. Point Cloudflare DNS to the records Vercel provides, then verify both hosts redirect to the preferred HTTPS address.
7. Pushes to `main` auto-deploy to production through the connected Vercel project.

Never expose `DATABASE_URL` in browser code or commit `.env.local`.

Form submissions are saved to Postgres and send an email notification through SMTP. For Google Workspace, set `SMTP_USER` to the mailbox address and `SMTP_PASSWORD` to a Google App Password. Keep the app password in the hosting provider's encrypted environment variables and never commit it.

## Featured listing report

Listing cards record anonymous impression and profile click events. To view a provider's daily totals for the last 30 days, run:

```bash
npm run db:listing-report -- provider-slug 30
```

The report stores no visitor identity or contact information.

The sitemap, robots file, metadata, structured data, social image, and canonical URLs are generated by the application. Location and care pages remain `noindex` until they contain published listings so search engines are not asked to index empty pages.

## Content workflow

- Add only real organizations with accurate source notes.
- Keep new records in `draft` until reviewed.
- Use the listing labels described on `/how-we-verify`.
- Record a review date and source URL for independently reviewed claims.
- Label paid placement as sponsored; payment must not determine verification status.

The original static prototype is preserved in `legacy-prototype/` for reference and is not served by the production app.

## Provider image storage

TreatmentLane-owned images are served from the `treatmentlane-images` Cloudflare R2 bucket through `https://images.treatmentlane.com`.

The provider image migration is a dry run unless `--apply` is passed. It writes a private rollback export before changing any provider row, uploads each object before updating its URLs, and records per-provider results under the ignored `work/image-migrations` directory.

```bash
npm run db:migrate-provider-images:r2
npm run db:migrate-provider-images:r2 -- --apply
```

External source hosts must be explicitly added to `R2_ALLOWED_SOURCE_HOSTS`. Copying from a host outside TreatmentLane also requires `--confirm-rights`. Use that option only after confirming TreatmentLane has permission to store and serve those files.

Restore a completed batch from its rollback file with:

```bash
npm run db:restore-provider-images -- --input=work/image-migrations/<rollback-file>.json
npm run db:restore-provider-images -- --input=work/image-migrations/<rollback-file>.json --apply
```
